Where each command gets its data
Already in the bot's model layer
getMovieNights · getGuildStats · getTopRatedMovies · getMostActiveRaters · getUserRatings · getUserTopRatedMovies · getGuildActiveMarathons · getMarathonItemsByMarathon · getTopBoardSuggestions · toggleMarathonAttendance
New queries needed
watch time · attendance-per-rater · date-bounded stats · paged history / ratings · wishlist read + random pick · board upvote write
Most have a backend twin already written — they need a bot-side copy carrying a // PARALLEL comment, per the convention in the repo.
Shared plumbing
Pagination reuses the stateless customId pattern /next just introduced — the page number rides in the id, every press re-queries, and the buttons survive a bot restart. One helper covers /history, /myratings and the board.

3 · /movienight — one door to all of it

Why it's cheap
Each command already has to build { embeds, components } from a guild id — that's the shape renderNextView established. The hub is a select menu that calls one of those renderers and hands the result to interaction.update().
One open question
This overlaps /help, which is a static list of command names. Either /help stays as the plain reference and /movienight is the live one, or /help simply becomes this. Your call — I'd keep both, since people type /help by reflex.
What this comes to.
  • Section 1 is pure embed-builder work — same data, new shape — plus three new stat queries. Fully unit-testable against the existing node --test setup, no Discord round-trip needed.
  • Section 2 adds three commands, one select menu and one write path (the board upvote), which is the only place here that changes data.
  • The /myratings overflow is a real bug, not a polish item — pagination is the fix, so that one is worth doing regardless of what else you keep.
  • Section 3 is the cheapest thing on the page if it goes last — it's a menu over renderers the first two sections already built. Built first, it would mean writing those renderers twice.
  • Anything here can be dropped without affecting the rest. If /wishlist or the /stats backdrop isn't worth it, say so and it goes.
